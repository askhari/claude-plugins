# Terraform conventions for this project

## File layout per module

```
module-name/
├── README.md          # Generated by terraform-docs — do not hand-edit
├── main.tf            # Primary resources
├── variables.tf       # All inputs
├── outputs.tf         # All outputs
├── versions.tf        # Provider + Terraform version constraints
├── locals.tf          # Computed values, only if non-trivial
└── examples/
    └── basic/
```

## Variables

- `description` and `type` are required on every variable.
- Use `validation` blocks for any non-trivial constraint.
- Boolean variables: prefix with `enable_` or `create_`.
- Sensitive: mark `sensitive = true`.

## Outputs

- One output per logical concept. Don't return whole resource objects unless required by a consumer.
- Mark sensitive outputs explicitly.

## Provider configuration

- Configure providers at the root module only. Modules declare provider *requirements* in `versions.tf`, never provider *blocks*.
- Pin provider versions with `~>` to allow patch updates only on prod-touching repos.

## State

- Remote state with locking is required. No local state in this repo.
- State references between modules go through `terraform_remote_state` data sources or published module outputs — never by reading another module's `.tfstate` directly.

## Before declaring done

- [ ] `terraform fmt -recursive`
- [ ] `terraform validate`
- [ ] `tflint`
- [ ] `terraform-docs markdown table --output-file README.md <module-dir>`
- [ ] `terraform plan` output reviewed and attached (for prod-touching changes)
