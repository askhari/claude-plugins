## What's in here

| Path | What it does | When it loads |
|---|---|---|
| `CLAUDE.md` | Project memory — always-true facts about this repo | Every turn |
| `settings.json` | Permissions and safety hooks (scaled to environment level) | Session start |
| `rules/*.md` | Path-scoped conventions | When files matching the rule's `applies_to` pattern are touched |
| `skills/*/SKILL.md` | Reusable workflows | When task description matches the skill, or invoked with `/<name>` |

No `agents/` personas are generated by default: the navigate orchestrator already claims a
task and runs an agent in a sandbox, so a static persona would just duplicate that role.

## How to use

- **For most work:** just talk to Claude normally. The skills and rules engage automatically
  when relevant.
- **Force a skill:** `/<skill-name>` as a slash command.

## How to extend

- New project-specific convention? Add a file to `rules/`. The frontmatter `applies_to` field
  controls when it loads.
- New repeatable workflow? Create `skills/<name>/SKILL.md` with a frontmatter `description`
  that explains when to use it.

## When to regenerate

Re-run `scaffold-skills` only if the project's stack changed substantially (new language, new
IaC tool, moved to/from prod). It reconciles additively — it won't clobber your hand-edits.
For incremental tweaks, edit the files directly; they're plain markdown and JSON.

## What was NOT generated

`scaffold-skills` only generates `.claude/` content. Project structure
(`.github/workflows/`, `terraform/`, `src/`, etc.) is your responsibility (and the
orchestrator's).
